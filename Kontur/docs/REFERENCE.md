# Kontur — справочник по формату сцены

Сцена — обычный JSON. Всё время — в секундах, углы — в градусах, координаты — в пикселях
(начало — левый верхний угол, ось Y вниз).

```json
{
  "version": 1, "width": 1920, "height": 1080, "duration": 6, "fps": 60, "loop": true,
  "background": "#0d0f1a",
  "nodes": [ { "id": "c1", "type": "circle", "parent": null, "props": {}, "keys": {}, "mods": [] } ]
}
```

`background` — цвет или градиент. Порядок `nodes` = порядок отрисовки (ниже в списке — выше на экране).

Любой узел может иметь свойство `d` (или ключи `d`) — тогда его форма задаётся им, и её можно **морфить**.

### Общие свойства
- Трансформация: `x`, `y`, `rotation`, `scale`, `scaleX`, `scaleY`, `skewX`, `anchorX`, `anchorY` (точка поворота в локальных координатах), `opacity`.
- Заливка/обводка: `fill`, `stroke` (цвет или градиент), `strokeWidth`, `lineCap`, `lineJoin`, `dash` ([длины]), `dashOffset`, `fillRule`.
- Прорисовка контура: `trimStart`, `trimEnd`, `trimOffset` (0..1, смещение циклически).
- Эффекты: `blur`, `glow: {blur, color, strength}`, `shadow: {x, y, blur, color, opacity}`, `blend` (mix-blend-mode: screen, multiply, …).
- Маски: `clip: "<id>"`, `mask: "<id>"` — узел-маска (лучше соседний по иерархии) не рисуется сам, а обрезает этот узел. `mask` — по яркости (белое видно).
- Время: `inPoint`, `outPoint` (окно видимости), `timeOffset` (задержка), `timeScale` (скорость).
- Размножение: `repeat: {count, x, y, rotation, scale, opacity, cx, cy, delay, reverse}` — копии с накопительной трансформацией и задержкой во времени (каскад/волна). `rotation` вращает вокруг (`cx`, `cy`) в координатах родителя; `scale` уменьшает каждую копию относительно её собственного центра (`scaleAround: true` — относительно `cx`, `cy`).

### Цвета и градиенты
Цвета: `#rgb`, `#rrggbb(aa)`, `rgb()/rgba()`, `hsl()/hsla()`, имена. Интерполяция идёт в OKLab — переходы без «грязи».

```json
{ "type": "linear", "angle": 45, "length": 300, "stops": [[0, "#f0abfc"], [1, "#22d3ee"]] }
{ "type": "linear", "x1": -100, "y1": 0, "x2": 100, "y2": 0, "stops": [[0, "#fff"], [1, "#000", 0.5]] }
{ "type": "radial", "cx": 0, "cy": 0, "r": 120, "fx": -30, "fy": -30, "stops": [{ "offset": 0, "color": "#fff" }, { "offset": 1, "color": "#f60" }] }
```
Координаты градиента — в локальной системе узла. Градиенты с одинаковым числом стопов плавно интерполируются (и с цветом тоже).

### Описания фигур (для `d` и морфинга)
- строка SVG path: `"M0 0 C50 -80 100 80 150 0"` (M L H V C S Q T A Z, абсолютные и относительные)
- `{"shape":"circle","r":100}`, `{"shape":"ellipse","rx":..,"ry":..}`, `{"shape":"rect","width":..,"height":..,"radius":..}`
- `{"shape":"polygon","sides":6,"radius":100,"cornerRadius":10}`, `{"shape":"star","points":5,"outerRadius":100,"innerRadius":45,"cornerRadius":0}`
- `{"shape":"heart","size":200}`, `{"shape":"line","x1":..,"y1":..,"x2":..,"y2":..}`, `{"shape":"blob", ...параметры blob}`
- `{"points":[[x,y],...], "smooth":true, "closed":true, "tension":1}`

Морфинг работает между **любыми** фигурами: число сегментов выравнивается, начальные точки и направление обхода подбираются автоматически, разное число подпутей допускается (лишние «вырастают» из центра).

## Растровые слои (`image`)

- `src` — путь к файлу (относительно файла сцены или абсолютный), `https://…` или `data:` URI. PNG, JPG, WebP, GIF, SVG.
- `width`, `height` — размер на сцене; `fit`: `stretch` (по умолчанию), `contain`, `cover`.
- `pixelated: true` — без сглаживания при масштабировании (пиксель-арт).
- Спрайт-лист: `sheet: {cols, rows, count, fps, frameWidth, frameHeight, loop}` — кадры сменяются с частотой `fps`
  или по анимируемому свойству `frame` (номер кадра, например `keys.frame`).
- Работают все общие свойства: трансформации, `opacity`, `blend` (`multiply`, `overlay`, `screen`… — удобно для фактур),
  `blur`, `glow`, `shadow`, `clip`/`mask`, ключи и модификаторы. Ключами можно менять и `src` (подмена картинки).
- При рендере в PNG/видео и экспорте в HTML локальные файлы встраиваются автоматически, сцена остаётся лёгкой.
- MCP-инструмент `image_add` копирует файл в `assets/` рядом со сценой и берёт размер из файла.

## Дизеринг теней

Упорядоченный растр вместо плоской заливки — ретро/пиксельный вид теней и переходов.

- Пометьте теневые слои: `"shade": true` (или объект с переопределениями: `"shade": {"density": [0.2, 1], "angle": 45}`).
- Включите глобально в сцене:
  ```json
  "dither": { "enabled": true, "pattern": "bayer4", "cell": 3, "density": 0.6, "angle": 90 }
  ```
  Выключение `enabled: false` возвращает плоские тени — без правки узлов.
- Принудительно для одного узла (независимо от переключателя): `"dither": { "pattern": "dots", "density": 0.5 }`; `"dither": false` — запретить.
- `pattern`: `bayer2`, `bayer4`, `bayer8`, `dots` (кластерные точки), `lines`, `diagonal`.
- `cell` — размер «пикселя» растра в px (в локальных координатах узла).
- `density` — доля закрашенных точек 0..1, либо `[от, до]` — плавный переход вдоль направления `angle`
  (0° — слева направо, 90° — сверху вниз). Уровни вложенные, поэтому переход без швов.
- `color` — цвет растра (по умолчанию — заливка узла). Обводка узла рисуется как обычно.
- `density` и весь объект можно анимировать ключами.
- MCP: `dither_set` — включить/выключить, сменить узор, пометить узлы тенями.

## Именованные клипы

Клипы — именованные отрезки общей шкалы времени. Анимации idle, walk и talk раскладываются на одной шкале друг за другом:

```json
"clips": [
  { "name": "idle", "start": 0,   "end": 2,   "loop": true },
  { "name": "walk", "start": 2,   "end": 3.2, "loop": true, "fps": 12 },
  { "name": "talk", "start": 3.2, "end": 5,   "loop": false, "next": "idle" }
]
```
- `loop: false` + `next` — что играть после окончания (в студии и в экспорте для Godot и Unity).
- `fps` — частота кадров клипа при экспорте в спрайты.
- Студия: список «Клип» и полосы клипов на линейке; MCP: `clip_set`, `clip_remove`; `render_contact_sheet` и `export` принимают `clip`.
- В коде: `player.setClip('walk')`, `clipRange(scene, 'walk')`, `clipTime(scene, 'walk', localT)`.

## Символы и экземпляры

Символ — набор узлов со своей шкалой времени (персонаж, иконка, цикл ходьбы), который рисуют узлы `instance`.
Правка символа меняет все экземпляры.

```json
"symbols": {
  "spark": { "duration": 1, "nodes": [ { "id": "p", "type": "star", "props": { "fill": "#ffd060" }, "keys": { "rotation": [[0, 0], [1, 72]] } } ] }
},
"nodes": [
  { "id": "s1", "type": "instance", "props": { "symbol": "spark", "x": 100, "y": 200 } },
  { "id": "s2", "type": "instance", "props": { "symbol": "spark", "x": 300, "y": 200, "timeOffset": 0.5, "timeScale": 2 } }
]
```
- Узлы символа — как в сцене (`parent` — внутри символа), координаты — от точки экземпляра.
- Время символа: локальное время экземпляра (`timeOffset`, `timeScale`, `inPoint`/`outPoint` — как у любого узла);
  по `duration` символа — по кругу (`loop`, по умолчанию) или с остановкой на конце (`loop: false`).
  `symbolTime` — явное время символа (можно анимировать ключами).
- Символы могут содержать экземпляры других символов (не себя: цикл — ошибка проверки).
- Состояния, `only` и IK основной сцены внутрь не проходят; IK внутри символа работает.
  У внутренних элементов нет `data-node`: в студии выбирается экземпляр.
- MCP: `symbol_define` (из `nodes` или из поддерева `from` с заменой экземпляром), `symbol_remove`;
  в коде: `ops.defineSymbol`, `ops.symbolFromNode`, `ops.removeSymbol`.

## Маркеры

Именованные точки шкалы — события для кода и экспорта: `"markers": [{ "t": 1.5, "name": "boom", "data": { "strength": 2 } }]`.
- Плеер: `player.onMarker((m, player) => …)` — при прохождении маркера во время воспроизведения (и через конец цикла).
- `markersCrossed(scene, t0, t1, { wrap })` — какие маркеры лежат в (t0, t1].
- Экспорт в Lottie — `markers`. MCP: `marker_set`, `marker_remove`.

## Текст по кривой

У `text` свойство `path` — id узла (его форма со сдвигом x/y), строка `d` или описание фигуры; `pathOffset` (0..1, можно
анимировать) — сдвиг начала вдоль пути, `textAlign` — выравнивание относительно него. Путь задаётся в координатах
родителя текста, собственные x/y/поворот текста тоже применяются — обычно у такого текста `x = y = 0`.

```json
{ "id": "arc", "type": "path", "props": { "d": "M100 300 Q400 50 700 300", "stroke": "#888" } },
{ "id": "title", "type": "text", "props": { "text": "По дуге", "path": "arc", "fontSize": 40 }, "keys": { "pathOffset": [[0, -0.5], [3, 0.5]] } }
```

## Импорт SVG и экспорт в Lottie

- `svg_import` (в коде `importSVG(text)` → `{ nodes, width, height, warnings }`, `insertSVG(scene, text, opts)`):
  группы, `rect`/`circle`/`ellipse`/`line`, `path`/`polygon`/`polyline`, `text`, `image`, `<use>` и `<symbol>`,
  простые CSS-правила из `<style>`, наследование оформления, линейные и радиальные градиенты (в т.ч. по рамке
  фигуры). Трансформации раскладываются в `x`, `y`, `rotation`, `skewX`, `scaleX`, `scaleY`. Не переносятся:
  clip-path, mask, filter, pattern, marker, SMIL — о них предупреждения.
- `export` с `format: "lottie"` (в коде `exportLottie(scene, { fps, tolerance })` → `{ lottie, warnings }`):
  кадры движка сэмплируются, поэтому переносится всё, что он считает (пружины, выражения, IK, морфинг, повторы,
  символы). Трансформации, прозрачность, формы, сплошные и градиентные краски, толщина и штрихи обводки — ключами;
  обрезка обводки — Trim Paths; лишние ключи отбрасываются (`tolerance` — допуск формы, 0.25). Не переносятся
  текст, растр, маски и обрезка, фильтры, режимы наложения и дизеринг.

## Рельеф и карты нормалей

Карта нормалей строится по карте высот, которую движок рендерит в режиме `mode: 'height'`:
каждая фигура — «подушка» высотой `height`, поднимающаяся от края на `depth` по профилю за `bevel` пикселей.
Порядок слоёв сохраняется: верхняя фигура перекрывает нижнюю, на стыках получаются фаски и канавки.

- Сцена: `"relief": { "height": 0.5, "depth": 0.3, "bevel": 8, "profile": "round", "luma": 0.25 }`.
- Узел (наследуется детьми): `"relief": { "height": 0.6, "depth": 0.4, "bevel": 18, "profile": "round" | "linear" | "sharp" | "flat", "invert": true }`;
  `"relief": false` — узел не участвует. Слои с `blend` и полупрозрачные (opacity < 0.6) не участвуют автоматически.
- Растровые слои: рельеф из яркости картинки (`luma`) плюс фаска по альфе.
- `normalMap` у растрового слоя — путь к готовой карте нормалей (переносится в манифест экспорта).
- Генерация: MCP `normal_map_generate` — для кадра сцены, набора узлов или растрового файла; настройки
  `strength`, `blur`, `bevel`, `depth`, `height`, `profile`, `detail` (рельеф из яркости цвета), `detailRadius`,
  `luma`, `yUp` (true — OpenGL/Godot, false — DirectX), `invertX`; для файлов `base`, `invertLuma`, `lumaBlur`.
  Возвращает карту и превью освещения.

## Экспорт в Godot 4

Импорт SVG в Godot не понимает фильтры (свечение, размытие, тени), режимы наложения и растр-паттерны.
`compat_check` перечисляет такие места. Экспорт `format: "godot"` переносит сцену без потерь:

- сцена раскладывается на слои; узлы, которые не перекрываются, объединяются, чтобы слоёв было мало;
- статичные слои → `Sprite2D` с PNG, где эффекты уже запечены;
- анимированные слои → `AnimatedSprite2D`; каждый клип сцены становится анимацией SpriteFrames
  (одинаковые подряд кадры склеиваются через длительность кадра);
- режимы наложения → `ShaderMaterial` с `kontur_blend.gdshader` (multiply, screen, overlay, soft-light, …);
- `normals: true` → карты нормалей через `CanvasTexture` для 2D-света (`normals: { animated: true, … }` — и для кадров анимации);
- `kontur_player.gd` на корне: `play(&"walk")` синхронно переключает все слои, `next_clips` — переходы;
- `kontur_manifest.json` — описание слоёв, кадров и клипов для собственного конвертера.

Параметры: `fps` (12), `scale` (масштаб текстур), `clips` (какие экспортировать), `resPath` (по умолчанию `res://<имя папки>`).

## Экспорт в Unity

`format: "unity"`, `path` — папка внутри `Assets` проекта (например `<проект>/Assets/Kontur/room`). Для Unity 6 и 2022+,
URP с 2D Renderer (по умолчанию) или встроенный конвейер (`pipeline: "builtin"` — без света). Слои запекаются так же, как для Godot:

- `Layers/*.png` + `.meta` — спрайты (одиночные, опора слева сверху, без сжатия; в пиксельном режиме — фильтр Point;
  карты нормалей — вторичная текстура `_NormalMap` для 2D-света URP);
- `Animations/<клип>.anim` — по клипу сцены, кадры всех анимированных слоёв синхронно; `<title>.controller` — Animator:
  состояние на клип (имена как в Kontur), `loop: false` + `next` — переход по окончании;
- `<title>.prefab` — корень с `SortingGroup`, `Animator` и `KonturPlayer`; слои — `SpriteRenderer` по порядку;
  варианты состояний — объекты, которые включает `SetState`; свет — `Light2D` (точечные + общий `Ambient`);
- режимы наложения — материалы `Materials/Kontur_<режим>.mat` с шейдером `Kontur/Sprite Blend`;
- `Assets/Kontur/Runtime/KonturPlayer.cs` и `KonturBlend.shader` — один раз на проект;
- `kontur_manifest.json` — описание слоёв, как у Godot.

Из кода: `GetComponent<KonturPlayer>().Play("walk")`, `CurrentClip`, `SetState("locker", "open")`, `GetState("locker")`.
GUID файлов постоянные: повторный экспорт в ту же папку обновляет картинки, не ломая ссылки в сценах Unity.

Параметры: `fps`, `scale`, `clips`, `normals`, `title` (имя префаба, по умолчанию `KonturScene`) — как у Godot;
`ppu` (100 — пикселей сцены на единицу Unity), `origin` (`center` — центр сцены в точке префаба, или `top-left`),
`pipeline` (`urp` | `builtin`), `colorSpace` (`linear` | `gamma`; по умолчанию читается из `ProjectSettings` проекта).

Цвет. Unity в Linear-проекте смешивает цвета в линейных значениях, Kontur (как браузер) — в sRGB. Шейдер наложения
пересчитывает слой так, что multiply совпадает с Kontur, screen — точнее обычной полупрозрачности Unity, overlay,
soft-light и hard-light — удвоенным умножением (верно на тёмном фоне), darken, lighten, color-dodge, difference и
plus-lighter — приблизительно. Свет `Light2D` (интенсивность, спад, цвет, `Ambient`) подбирается численно под превью
Kontur `lit` с учётом того, как считает URP 17, поэтому цвета света в инспекторе темнее, чем в Kontur.
Имена на кириллице в файлах пишутся латиницей (`ходьба` → `hodba`), в Animator остаются как есть.

## Кости и IK

Кость — группа с `bone: true`: её `x`, `y` — сустав в координатах родителя, `rotation` — поворот звена,
`boneLength` — длина (для рисования в редакторе; без неё длина берётся до первой дочерней кости).
Дети кости (руки, ноги, части тела) просто вложены в неё и поворачиваются вместе с ней.

Двухзвенный IK задаётся на **конечном** узле цепочки (стопа, кисть): `props.ik = { target, bend, flip, orient, orientOffset, enabled }`.
Его родитель и дед (голень и бедро) поворачиваются так, чтобы опорная точка конечного узла
совпала с опорной точкой узла `target` (обычно пустая группа-цель).
- `bend` 1 | −1 — в какую сторону сгибается сустав (по умолчанию — как в текущей позе), `flip` — обратная сторона;
- `orient: true` — конечный узел повторяет поворот цели (стопа ровно стоит на полу), `orientOffset` — добавка в градусах;
- `ikWeight` (0..1, можно анимировать) смешивает IK с ключами поворота: 0 — только ключи, 1 — только IK.

Анимируйте цель (ключи `x`, `y` у `target`), а не углы звеньев. MCP: `bone_mark`, `ik_set`.

```json
{ "id": "foot", "type": "group", "parent": "shin", "props": { "x": 120, "y": 0, "ik": { "target": "foot_target", "orient": true } } }
```

## Состояния объектов

Именованные варианты, которые подменяют свойства узлов поверх ключей: дверь открыта/закрыта, лампа вкл/выкл.

```json
"states": [
  { "name": "locker", "default": "closed",
    "values": { "closed": {}, "open": { "door": { "visible": false }, "door_open": { "visible": true } } } }
]
```

Порядок значения свойства: вариант состояния → ключи → `props`. Выбор варианта не хранится в сцене:
его передают при рендере (`render_frame` / `render_contact_sheet` с `states: {"locker": "open"}`, `new Player(el, scene, { states })`,
`player.setState('locker', 'open')`), без выбора берётся `default`. В Godot экспорт делает слой на вариант
и `$Scene.set_state(&"locker", &"open")`, в Unity — `GetComponent<KonturPlayer>().SetState("locker", "open")`. MCP: `state_set`, `state_remove`.

## Свет и пиксельный режим

- **Свет.** Узлы `light` + `scene.ambient` (общий фон освещения, по умолчанию `#4a4f5c`). Превью считает свет по карте
  рельефа (как 2D-свет Godot с картой нормалей): `render_frame` с `lit: true`, кнопка «Свет» в редакторе.
  Затухание: `(1 − d/radius)^falloff`, `z` — высота источника над сценой. В Godot — `PointLight2D`, в Unity — `Light2D` (URP).
- **Пиксельный режим** `scene.pixel = { enabled, size, palette, aa }`: кадр рисуется в разрешении
  (ширина/size × высота/size) без сглаживания и увеличивается «ближайшим соседом» — вектор выглядит как пиксель-арт.
  `palette` — список цветов, к которым приводится кадр; `aa: true` оставляет сглаживание краёв.
  MCP: `pixel_set`, `render_frame` с `pixel: true`.

## 2.5D: отложенный свет

Сцена остаётся обычной векторной сценой, но узлы несут сведения о 3D-поверхности, а камера знает, как мир
проецируется на экран. Из этого рендер собирает проходы (G-буфер) и считает свет как в 3D: солнце с тенями
лучами, небо и отражённый свет, AO, лампы с тенями, блики, свечение, туман, bloom и стилизацию.

### Камера `scene.camera3d`
```json
"camera3d": { "hor": 280, "f": 1500, "camH": 4.2, "dz": 2.5, "cx": 1280 }
```
Мир: 1 единица ≈ 1 м, Y вверх, Z вглубь от камеры. Проекция `P([X,Y,Z]) = [cx + f·X/(Z+dz), hor + f·(camH − Y)/(Z+dz)]`.
`hor` — экранная Y горизонта, `f` — фокус в px, `camH` — высота камеры, `dz` — отъезд назад, `cx` — точка схода
(по умолчанию середина кадра). Подбор по росту персонажа (1,7 м) у низа кадра: `camH = 1.7·(bottom − hor)/charPx`.
MCP: `camera3d_set` (с `charPx`; пересобирает группы `world_build`).

### Поверхность узла `props.surface`
| Поле | Наследуется | Смысл |
|---|---|---|
| `plane` `[nx,ny,nz,d]` | да | плоскость грани `n·P = d` — по ней восстанавливается позиция пикселя; `"inherit"` — явно от родителя |
| `normal` `[x,y,z]` | да | нормаль для света (по умолчанию — нормаль плоскости); к камере — `[0,0,-1]` |
| `u`, `v` | да | оси грани (по умолчанию из нормали: стена — u по горизонтали, v вверх; пол — u = X, v = Z) |
| `tilt` `[du,dv,k]` | нет | наклон нормали относительно родительской грани: `norm(n + u·du·k + v·dv·k)` — фаски кирпича, доски |
| `spec` 0..1 | да | сила блика (штукатурка 0,1, камень 0,25, металл 0,6, стекло 0,9, вода 1) |
| `emissive` | да | цвет свечения (окна, лампы) |
| `base` | нет | тело: пишет плоскость, нормаль и d, перекрывает всё за собой во всех проходах |
| `bump` | нет | деталь меняет только нормаль (ставится сам при `normal`/`tilt` у узла) |
| `ink`, `sw` | нет | контур фигуры в проходе ink и его толщина |
| `tag` | да | метка маски `mask:<tag>`; персонажи — `"chr"` (смягчённый свет, без жёстких теней) |
| `sky` | да | фигура неба: не покрывает кадр, остаётся фоном |

`surface: false` снимает поверхность с ветки. Узлы без поверхности в проходы данных не пишутся (свет берётся
от поверхности за ними), а непрозрачные — перекрывают в свечении, масках и контуре. Покрытые, но без плоскости
пиксели (рисованные персонажи без surface) освещаются небом и солнцем как обращённые к камере.

**Окклюдеры** `props.occluder`: `{ box: [x0,x1,y0,y1,z0,z1] }`, `{ boxes: […] }`, `{ tris: [[[X,Y,Z]×3], …] }` —
геометрия для лучей теней (скрытые узлы не отбрасывают тень). **Свет** — узел `light` с `p3: [X,Y,Z]`
(мировая позиция; экранные x, y и радиус считаются камерой), `radius` в метрах, `group` (`lamp`, `window`,
`candle` — множители из `lighting.groups`), `shadows`.

### Проходы
`renderSVG(scene, t, { mode })`: `normal` (rgb = (n·0,5+0,5)·255, фон прозрачный), `plane` (нормаль плоскости,
альфа — геометрия), `planeD` (q = round((d+200)·100): R — старший байт, G — младший, B — блик·255), `emissive`
(на чёрном), `ink` (контур чёрным на белом), `cover` (покрытие не-небом), `mask:<tag>`. В проходах выключены
фильтры, наложения и дизеринг, картинки заливаются цветом по альфе; вырожденные фигуры тоньше 0,3 px
не рисуются, у одиночных фигур прозрачность идёт в `fill-opacity` (без швов между соседями).
MCP: `render_passes` (PNG всех проходов + `normal_map` в соглашении 2D-движков).

### Свет `scene.lighting`
```json
"lighting": { "preset": "night", "sun": { "dir": [0.35, 0.85, -0.4], "energy": 0.3 }, "exposure": 0.8 }
```
Пресеты: `day` (рисованный день), `comic` (закат, комикс), `night` (ночь с фонарями), `pixel` (пиксель-арт со светом),
`golden` (золотой час, иллюстрация), `dusk` (сумерки с фонарями), `cinematic` (GTAO, контактные тени, GI×2, глубина
резкости, автоэкспозиция, AgX, хроматическая аберрация и зерно).
Поля поверх пресета: `sun {dir — направление на солнце, color, energy, wrap, shadows}`, `sky {color, energy}`,
`ground {color, energy}`, `ao {strength, radius}`, `fog {color, density, start, amount}`, `bloom {strength, threshold}`,
`exposure`, `saturation`, `tonemap` (`aces`|`hue`|`agx`|`none`), `emissive`, `specular`, `groups {lamp, window, candle}`,
`lightShadows`, `characters {tag, amount}`, `backdrop {mode: albedo|gradient, colors, clouds, stars, moon}`.
Цвета света — доли без гаммы (`#ffc070` → [1, 0,75, 0,44]) или `[r,g,b]`. MCP: `lighting_set`.

Цвет «как в иллюстрации» (всё выключено по умолчанию; `true` — значения по умолчанию):
- `paint {chroma 0.45, shadow [0.55,0.45,0.75], amount 0.4, desat 0.2, range [0.12,0.7], fill 0.03}` — живописное
  затенение. Цвет солнца и неба окрашивает поверхность лишь на долю `chroma`, поэтому розовая стена остаётся розовой.
  Тень (доля от «полного света» в пределах `range`) сдвигает тон к `shadow` на `amount` без лишнего затемнения,
  теряет насыщенность на `desat` и подсвечивается заливкой `fill`. Свет ламп в этом не участвует: тёплые пятна
  остаются тёплыми.
- `tonemap: "hue"` — ACES по максимуму канала: тон и насыщенность сохраняются, очень яркое плавно уходит в белый
  (ACES по каналам уводит насыщенный оранжевый в жёлтый). `"agx"` — AgX: мягче и бледнее в светах.
- `aerial {color, start 8, density 0.05, amount 0.7, desat 0.45, shift 0.5, lift 0.06}` — воздушная перспектива:
  после `start` м цвет теряет насыщенность, сдвигается к `color` и чуть светлеет. В отличие от `fog`, яркость
  кадра почти не меняется.
- `ao.color` — цвет, в который уходит затенённое (AO), вместо чёрного.
- `grade.matchRef` — палитра с референса: `"путь"` (PNG; JPEG, WebP и прочее через ffmpeg) или
  `{src, amount 0.6, lum 0.35, chroma 0.6, zones true}`. Переносится в Lab: средняя яркость и контраст (вес `lum`),
  разброс хромы (вес `chroma`), оттенок по зонам теней, середины и светов (`zones`). Применяется до остальной
  цветокоррекции `grade`.
- `textureFilter` (`true` по умолчанию) — фильтрация попиксельных фактур по следу пикселя на поверхности.
  Вдали берётся до 8 выборок вдоль длинной оси следа, ещё дальше — средний цвет фактуры; мелкие октавы `noise`
  и `bump` гаснут. Так плитка и доски не дают муар. Вблизи кадр не меняется. `false` — одна точка на пиксель.

Постобработка — окклюзия, глобальное затенение, оптика (всё выключено по умолчанию; `true` — значения по умолчанию):
- `ao.mode: "gtao"` — горизонтная окклюзия (GTAO/HBAO) вместо прежнего SSAO. В `dirs` (4) экранных направлениях
  ищется наивысший горизонт с обеих сторон в радиусе `radius` **метров** (`steps` 8 выборок на сторону, затухание
  после доли `falloff` 0.6), видимость косинусно взвешена. `bent` (true) — изогнутая нормаль: свет неба и земли
  берётся по среднему свободному направлению (дно щели получает небо сверху, а не по своей нормали).
  `multiBounce` — многократный отскок (Jimenez 2016): светлые поверхности теряют в щелях меньше света.
  Персонажи-спрайты AO не темнит. `ao.color` и `ao.strength` работают и здесь.
- `contactShadows {length 0.4, steps 14, thickness 0.12, strength 1}` — контактные тени: короткий луч от точки к солнцу
  по буферу глубины. Ловит тени мелких деталей и ступеней, которых нет среди окклюдеров BVH. Умножаются на тень солнца.
- `gi.bounces` (1…3) — отскоки отражённого света: второй собирает уже отражённый свет (внутренние углы светлеют,
  цветные рефлексы уходят дальше). `gi.scale` — радиус выборок.
- `dof {focus "auto", aperture 1, maxBlur 14, near true, samples 24}` — глубина резкости. Кружок рассеяния
  `aperture·8·|1 − focus/глубина|` px (кадр 1280, масштабируется), не больше `maxBlur`; `focus` — метры или `"auto"`
  (медиана глубины в центре кадра). Сбор по диску Фогеля в HDR: яркие точки дают боке, задний план не наползает на
  резкий передний. Контур стиля `ink` размывается и бледнеет вместе с предметом. `near: false` — передний план резкий.
- `autoExposure {key 0.18, min 0.35, max 3, amount 1}` — экспозиция приводит среднюю логарифмическую яркость кадра
  (без 2% самых ярких: лампы, солнце) к `key`; умножается на `exposure`.

Порядок конвейера: G-буфер → материалы → тени солнца и контактные → AO → солнце, небо, лампы → GI → сборка (живописные
тени, туман, воздушная перспектива) → небо → SSR → объёмный свет → глубина резкости → bloom → автоэкспозиция →
тонмаппинг → `grade.matchRef` → `grade` → цепочка стилей. Код этапов — `mcp/lit/*.mjs`, оркестратор — `mcp/lighting.mjs`.
В ответе `render_frame` (`lit: "deferred"`) — время этапов и список включённых эффектов.

### Стиль `scene.style`
Цепочка по порядку: `cel {steps, detail}`, `hatch {below, period, color}`, `kuwahara {radius}`, `paint {radius, sharpness}`,
`pixelate {size, colors, bayer}`, `ink {strength, color ("albedo"), darken, depthWidth, refDepth}`, `paper {strength, color,
tint, scale}`, `vignette {strength}`, `fxaa {threshold 0.125, subpix 0.75}` (сглаживание краёв), `sharpen {amount 0.4}`
(адаптивная резкость по мотивам CAS), `chromatic {amount 1.5}` (хроматическая аберрация, px у края кадра 2560),
`grain {amount 0.04, size 1.2, color false, seed}` (зерно плёнки, сильнее в средних тонах); `enabled: false` выключает звено.
Без `style` берётся стиль пресета света. Размеры заданы для ширины 2560 px и масштабируются. MCP: `style_set`.

### Сборка мира и материалы
`world_build` строит узлы из 3D-описания (метры, Y вверх, Z вглубь) с поверхностями и окклюдерами; описание
хранится в `props.world3d` группы и пересобирается при смене камеры (`camera3d_set`). `material_apply` кладёт на
любую грань с `surface.plane` материал (`brick`, `stone`, `plaster`, `wood`, `tile`, `cobble`, …) — детали с
наклонёнными нормалями, обрезанные контуром грани.

Параметры сборки:
- `v` — версия. **2** (по умолчанию для новых миров): у каждого предмета свой подсид `hashSeed(seed, id)`, у каждой
  грани — свой, поэтому раскладка кирпича, горящие окна и т. п. не зависят от камеры и от правок других предметов.
  Предметы без `id` получают id по номеру при первой сборке; id узлов — `<группа>_<id>-<k>`. Повторяющийся `id` —
  ошибка. **1** — прежняя сборка (общий поток случайных чисел); так собираются старые миры без `v`.
- `lod` — детализация: 0 полная, 1 (v2 по умолчанию) — без фасок, плитки и булыжника мельче ~1 px, 2 — грубее.
- `merge` (v2 — `true`) — детали одной грани с одинаковой заливкой сливаются в составные пути с сохранением
  порядка рисования: в десятки раз меньше узлов при том же виде.
- `pan: [[t, dx], …]` — проезд камеры вбок на `dx` м: группы предметов получают ключи `x = −f·dx/(Z + dz)` по
  ближней глубине (точно для граней z = const, приближённо для объёмных; свет и тени остаются на месте).
- `tess` — адаптивная тесселяция кривых: тела вращения (`lathe`, `cyl`, фонтаны, лампы), сферы, диски, арки и их
  окклюдеры. `true` — сегмент дуги около 6 px на экране, число — px на сегмент, `{px, min 8, max 96}`. Ближние предметы
  глаже (силуэт, градиент нормали и тень без граней), дальние проще. По умолчанию выключена — прежние постоянные числа
  граней; неровные контуры (`wob`) не меняются.
- `seed`, `sky` (три цвета неба), `occ: "manual"` или `"boxes"` (тени только от явных окклюдеров), `materials` (попиксельные).

Ответ `world_build`: число узлов, источников и окклюдеров, предметы с наибольшим числом узлов, ошибки и
предупреждения схемы (обязательные поля, типы, неизвестные поля с подсказкой ближайшего имени), подсказки. В v2
неизменённые предметы при пересборке берутся из кэша. `world_item` правит один предмет: по `id` или `index` —
`item` (заменить), `patch` (дополнить, `null` удаляет поле), `remove`, либо `add` (новый предмет).

- **text** `{on:{on}!, a=0, b=0, text!, size=0.3, color=#2e2a3c, font, weight, spacing, emissive}` — надпись на грани: вывеска, номер дома
- **array** `{item:{…}!, count!, step:[X,Y,Z]!, at:[X,Y,Z]=[0,0,0]}` — ряд копий предмета: item задан в своих координатах, копия k сдвинута на at + k·step (сдвигаются x, y, z, X, Y, Z, y0, p, ps, holes, on, spring, top)
- **scatter** `{item:{…}!, area:{…}!, count!, minDist=1, y=0}` — рассыпь копий предмета по площадке (случайно, не ближе minDist): item — в своих координатах вокруг (0, 0, 0)
- **slab** `{x:[a,b]!, z:[a,b]!, y=0, t=0.2, color=stone, mats:{грань:[материал,цвет,опции]}, occ}` — плита толщиной t (балкон, козырёк, ступень): коробка с видимым дном
- **ramp** `{x:[a,b]!, z:[a,b]!, y:[a,b]!, base=0, color=stone, mat, matColor, sides=true}` — пандус: наклонный верх от высоты y[0] у z[0] до y[1] у z[1], боковины
- **road** `{x:[a,b]!, z:[a,b]!, y=0, color=#5d5752, lines=true, lineColor=#e8dcc0, curb=0.15, curbW=0.25, curbColor=stoneHi, walk=2, walkColor=stone, walkMat=slabs}` — улица: проезжая часть, разметка, бордюры и тротуары
- **window** `{on:{on}!, a, b, w=0.84, h=1.2, lit, shut, box, ajar=0}` — окно с наличником, переплётом, ставнями, ящиком цветов
- **door** `{on:{on}!, a, b, w=1.1, h=2.1, color=wood}` — арочная дверь
- **pipe** `{on:{on}!, a, b, h}` — водосточная труба
- **ivy** `{on:{on}!, a, b, w=1.5, h=3, density=80}` — плющ

## Правки из редактора (`*.edits.json`)

Если сцена собирается скриптом (`X.build.mjs` пишет `X.kontur.json`), ручные правки в редакторе
не пишутся в `X.kontur.json`, а копятся рядом в `X.edits.json` — разницей со сценой из скрипта:

```json
{ "kontur": "edits", "version": 1,
  "scene": { "ambient": "#30364a" },
  "nodes": { "table": { "props": { "x": 812 }, "base": { "type": "group", "parent": null }, "was": { "x": 760 } } },
  "removed": ["dust_3"],
  "order": [ { "id": "path", "parent": null, "after": "sock", "add": { "id": "path", "type": "path", "props": { "d": "M0 0 L40 0" } } } ] }
```
`nodes` — изменённые свойства (`was` — значения из скрипта на момент правки, по ним видно, что скрипт их потом поменял),
`removed` — удалённые узлы, `order` — добавленные (`add`) и переставленные узлы.

Скрипт можно перезапускать: сервер замечает новый `X.kontur.json` и накладывает правки заново.
Если объект из правок исчез (скрипт переименовал id), правка не теряется — она остаётся в файле, а `edits_info`
и вкладка «Сцена» показывают предупреждение. Свои скрипты запекания читают сцену через `applyEdits(base, edits)`
(в проекте игры — `loadScene()` из `art_src/kontur/lib.mjs`). MCP: `scene_open` с `edits: true|false`, `edits_info`, `edits_reset`.

## Ключевые кадры

```json
"keys": {
  "x":       [{ "t": 0, "v": 100, "ease": "outBack" }, { "t": 1.2, "v": 900 }],
  "fill":    [{ "t": 0, "v": "#ff0066" }, { "t": 2, "v": "#00ccff" }],
  "d":       [{ "t": 0, "v": {"shape":"circle","r":80} }, { "t": 1, "v": {"shape":"star","points":6,"outerRadius":110} }],
  "opacity": [[0, 0, "outQuad"], [0.5, 1]]
}
```
- `ease` у ключа задаёт кривую **до следующего** ключа. По умолчанию `inOutCubic`. `"hold": true` — ступенька.
- Сокращённая запись ключа: `[t, v, ease]`.
- Анимировать можно любое свойство: числа, цвета, массивы чисел, градиенты, фигуры (`d`), объекты (покомпонентно).

### Кривые (ease)
`linear`, `hold`, `in/out/inOut` + `Sine|Quad|Cubic|Quart|Quint|Expo|Circ|Back|Elastic|Bounce`,
`ease`, `ease-in`, `ease-out`, `ease-in-out`, `smooth`, `snappy`, `anticipate`,
`"cubic-bezier(0.2,0.8,0.2,1)"` или `[0.2,0.8,0.2,1]`,
`"spring(180,12,1)"` или `{"spring":{"stiffness":180,"damping":12,"mass":1,"velocity":0}}`, `{"steps":5}`.

## Пресеты
`popIn`, `fadeOut`, `drawOn`, `morphSequence`, `float`, `pulse`, `stagger`, `typewriter`, `orbitRing` — макросы,
которые раскладывают ключи и модификаторы (см. инструмент `preset_apply`).

## Рецепты плавности
- Плавный морфинг: `ease: "inOutCubic"` или `"inOutBack"` + небольшой `spin` во время перехода.
- «Живой» объект: `wiggle` по `x,y,rotation` с `freq` 0.2–0.6 и маленькой амплитудой.
- Пружинистый отклик: резкие ключи (`hold`) + модификатор `spring` (stiffness 60–200, damping 6–14).
- Волна по массиву: `repeat` + `oscillate` с `phaseStep` или `repeat.delay`.
- Прорисовка: `trimEnd` 0→1, затем `trimStart` 0→1 — «стирание»; кометы — короткий отрезок и анимированный `trimOffset`.
- Жидкие линии: `path` из точек + `deform` + `repeat` с `delay` (волна распространяется по копиям).
